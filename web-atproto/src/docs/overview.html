Identity the chain can check itself

Bluesky accounts are anchored in cryptography the contract can reproduce. A did:plc is the hash of a signed genesis operation; the operation log yields the account's repo signing key; the repo commit is signed by that key and commits to a Merkle search tree; the path to a record authenticates its bytes. The layer walks that chain in WASM, so the proof stands on the account's own signatures — nothing else.

no oracle

Self-contained proofs

A claim carries the identity history, the signed commit and the MST path. Every signature is checked on-chain; no off-chain attester is trusted.

reusable

One layer, many contracts

A shared crate and an immutable Verifier component. Build a new feature against it without re-implementing any atproto crypto.

bounded

Hardened for a VM

Low-S signatures, hash-linked MST, depth and size caps on every input, DAG-CBOR with no indefinite lengths. Reviewed internally, with no third-party audit yet. See the trust boundaries.

Everything a contract can prove

The layer exposes everything that is anchored and therefore provable trustlessly in WASM. The honest boundary matters: some atproto facts live in DNS or a PDS and cannot be proven on-chain — those are marked, and need an explicit attestation rather than a misleading check.
