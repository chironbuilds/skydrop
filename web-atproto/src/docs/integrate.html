Build on the layer

Just want to pay people for doing things on Bluesky? You don't need a policy for that: the Campaign contract covers it with no code. Write a policy when you need custom logic. All code below is for Ootle 0.49.

Two ways in. Link the atp-verify crate directly for the cheap hot path, or call the shared Verifier component from any contract. Then gate your own logic on the result.

1

Verify a post in your own template (crate)

Depend on atp-verify and prove a record is in the account's repo. Any failure aborts the transaction; after it returns, the record bytes are authentic.

// Cargo.toml: atp-verify = { path = "…" }
let chain = atp_verify::verify_plc_chain(&did, &ops).expect("invalid chain");
atp_verify::verify_record(
    &did, &chain.signing_key, commit, &mst_nodes, record,
    "app.bsky.feed.post", &rkey,
).expect("record not in repo");

// now trust the bytes: read any lexicon field
let text = atp_verify::record_text(record)?;
let subject = atp_verify::field_str(record, &["subject", "uri"])?;
2

Or call the Verifier component (any contract)

Pin the deployed Verifier's address. prove_record_field verifies and extracts in one call, so you never read an unverified field.

let uri: String = ComponentManager::get(verifier)
    .call("prove_record_field", args![
        did, ops, commit, mst_nodes, record,
        "app.bsky.feed.like", rkey, vec!["subject", "uri"],
    ]);
// uri is now proven to come from a like in `did`'s repo
3

Escrow against a policy, release with a badge

Deposits pin to the policy that governs them. Your policy verifies, then presents a proof of its badge to release — the escrow checks the badge id against the pinned policy.

// a new account's ledger is opened first; send both in one transaction
escrow.open_account(account_id);
// a sender escrows, pinned to your policy, metadata is yours to define
escrow.deposit(account_id, sender, refund_epoch, my_policy, metadata, funds);

// inside the policy, after verification succeeds:
let proof = self.badge_vault.create_proof();
let paid: Bucket = ComponentManager::get(self.escrow)
    .call("release", args![proof, account_id, index]);
// since Ootle 0.49 a proof shown to a callee stays yours: drop it or the transaction fails
proof.drop();

A complete policy, end to end

Here is a whole feature in one template: LikeGate pays a deposit to an account once it proves it liked a specific post. It shows every moving part — reading the pinned deposit, checking the shared chain floor, verifying a repo record, checking a field, and releasing with the badge. The target post is carried in the deposit's metadata, so one policy instance serves every campaign. A like is public, so anyone may submit the proof: the payout goes to the wallet the DID linked in the LinkRegistry, never to the submitter.

like_gate/src/lib.rs

// Deposit tuple mirrored from the escrow so deposits_for decodes:
// (sender, amount, refund_epoch, policy, metadata, created_epoch)
type Deposit = (RistrettoPublicKeyBytes, Amount, u64, ComponentAddress, Bytes, u64);

#[template]
mod like_gate {
    use super::*;

    pub struct LikeGate { escrow: ComponentAddress, badge_vault: Vault, link_registry: ComponentAddress }

    impl LikeGate {
        pub fn new(escrow: ComponentAddress, badge: ResourceAddress, link_registry: ComponentAddress) -> Component<Self> {
            Component::new(Self { escrow, badge_vault: Vault::new_empty(badge), link_registry })
                .with_access_rules(AccessRules::allow_all()).create()
        }

        pub fn receive_badge(&mut self, badge: Bucket) { self.badge_vault.deposit(badge); }

        // Anyone submits a like record in `did`'s repo whose subject is the target post.
        pub fn claim(&mut self, did: String, index: u32,
                     ops: Vec<Bytes>, commit: Bytes, mst_nodes: Vec<Bytes>,
                     record: Bytes, rkey: String) {
            // 1. the deposit must be ours; its metadata names the post that must be liked
            let me = CallerContext::current_component_address();
            let deps: Vec<Deposit> = ComponentManager::get(self.escrow)
                .call("deposits_for", args![did.clone()]);
            let dep = deps.get(index as usize).expect("no such deposit");
            assert!(dep.3 == me, "not a LikeGate deposit");
            let target = String::from_utf8(dep.4.to_vec()).expect("bad target");

            // 2. the chain must be current: a key the registry has seen rotated away proves nothing
            let ops_s: Vec<&[u8]> = ops.iter().map(|b| b.as_slice()).collect();
            let nodes: Vec<&[u8]> = mst_nodes.iter().map(|b| b.as_slice()).collect();
            let chain = atp_verify::verify_plc_chain(&did, &ops_s).expect("bad chain");
            let registry = ComponentManager::get(self.link_registry);
            let (floor, tip): (u32, Bytes) = registry.call("chain_pin", args![did.clone()]);
            assert!(chain.extends(floor, tip.as_slice()), "stale operation chain");

            // 3. verify the like record really is in the account's signed repo, and points at the target
            atp_verify::verify_record(&did, &chain.signing_key, commit.as_slice(),
                &nodes, record.as_slice(), "app.bsky.feed.like", &rkey).expect("bad proof");
            let subject = atp_verify::field_str(record.as_slice(), &["subject", "uri"]).expect("no subject");
            assert!(subject == target, "that like is for a different post");

            // 4. pay the DID's own linked wallet, proving our badge (the submitter gets nothing)
            let wallet: Option<ComponentAddress> = registry.call("binding_for", args![did.clone()]);
            let wallet = wallet.expect("link a wallet first");
            let proof = self.badge_vault.create_proof();
            ComponentManager::get(self.escrow).invoke("release_to", args![proof, did, index, wallet]);
            proof.drop();
        }
    }
}

Bounties: like, repost, follow, post

A bounty is the same idea scaled to many claimants: the funder escrows a pool of equal slots under one campaign id, each slot's metadata holding the engagement kind and the target. On atproto a retweet is a repost; likes, reposts and follows are all signed records with a subject, and a proof-of-post bounty checks a post's text instead, so one policy covers all four with a kind→collection map. Three rules make it safe: the campaign id names its funder (<funder key hex>:<name>) and only that funder's deposits count as slots — otherwise anyone could drop a junk slot at the front of someone else's pool and make every claim fail; one claim per account (dedupe by DID); and a claim-code post that binds the payout to the engager's own wallet, so a bystander can't claim someone else's repost to their address.

engagement_bounty/src/lib.rs (the claim method)

fn collection(kind: u8) -> &'static str {
    match kind { 0 => "app.bsky.feed.like", 1 => "app.bsky.feed.repost",
                 2 => "app.bsky.graph.follow", 3 => "app.bsky.feed.post", _ => panic!("unknown kind") }
}

// a slot is a deposit governed by this policy AND made by the campaign's funder
fn is_slot(d: &Deposit, me: &ComponentAddress, funder: &str) -> bool {
    d.3 == *me && key_hex(&d.0) == funder
}

pub fn claim(&mut self, campaign: String, did: String, claimant: RistrettoPublicKeyBytes,
             ops: Vec<Bytes>,
             e: Proofs,   // the engagement record (like / repost / follow / post)
             c: Proofs)   // a claim-code post that binds the payout
             -> Bucket {
    CallerContext::assert_badge_in_scope(&NonFungibleAddress::from_public_key(claimant));

    // one claim per account per campaign
    let done = self.claimed.entry(campaign.clone()).or_default();
    assert!(done.insert(did.clone()), "this account already claimed this bounty");

    // take the funder's next free slot; its metadata = [kind byte][target]
    let me = CallerContext::current_component_address();
    let funder = campaign_funder(&campaign);   // "<funder key hex>:<name>"
    let deps: Vec<Deposit> = ComponentManager::get(self.escrow).call("deposits_for", args![campaign.clone()]);
    let (idx, meta) = deps.iter().enumerate().find(|(_, d)| is_slot(d, &me, funder))
        .map(|(i, d)| (i as u32, d.4.clone())).expect("bounty is exhausted");
    let kind = meta.as_slice()[0];
    let target = String::from_utf8(meta.as_slice()[1..].to_vec()).unwrap();

    let chain = atp_verify::verify_plc_chain(&did, &slices(&ops)).expect("bad chain");
    let (floor, tip): (u32, Bytes) = ComponentManager::get(self.link_registry).call("chain_pin", args![did.clone()]);
    assert!(chain.extends(floor, tip.as_slice()), "stale operation chain");

    // 1. claim-code post binds the payout to this claimant's key (no front-running)
    atp_verify::verify_record(&did, &chain.signing_key, c.commit, &c.nodes, c.record,
        "app.bsky.feed.post", &c.rkey).expect("bad code proof");
    assert!(atp_verify::record_text(c.record)?.contains(&claim_code(&me.to_string(), &did, &claimant)),
        "missing claim code");

    // 2. the engagement itself matches the campaign target
    atp_verify::verify_record(&did, &chain.signing_key, e.commit, &e.nodes, e.record,
        collection(kind), &e.rkey).expect("bad engagement proof");
    match kind {
        3 => assert!(atp_verify::field_contains(e.record, &["text"], &target),   // post: text carries the phrase
                  "the post does not contain the required text"),
        2 => assert!(atp_verify::field_str(e.record, &["subject"])? == target),          // follow: subject is a DID
        _ => assert!(atp_verify::field_str(e.record, &["subject", "uri"])? == target),   // like / repost: subject.uri
    }

    // 3. release one slot to the bound claimant
    let proof = self.badge_vault.create_proof();
    let paid: Bucket = ComponentManager::get(self.escrow).call("release", args![proof, campaign, idx]);
    proof.drop();
    paid
}

This slot pool is limited to 64 slots per campaign by the Escrow's per-policy cap. For anything larger, use the Campaign contract, which has no such limit. The funder tops the pool up by escrowing more slots with the same metadata under the same campaign id; when the slots run out, the bounty is closed and any left are refundable after their epoch. A time-boxed campaign just sets that refund epoch to the deadline. slots_left(campaign) counts only the funder's own slots, so junk deposits never inflate it.

Pay-per-call with service auth

ServicePay turns a deposit into a metered credit line for an atproto service. The payer escrows credit for a DID with metadata price ++ provider DID \n payout account [\n method]. Each call, the user's PDS mints a service-auth JWT; anyone submits it and the policy pays exactly one call's price to the payout the user fixed up front. Whatever can't cover another call is kept as change for the payer.

service_pay/src/lib.rs (the redeem method, abridged)

pub fn redeem(&mut self, did: String, index: u32, ops: Vec<Bytes>, token: String, payout: ComponentAddress) {
    let dep = self.our_deposit(&did, index);          // dep.3 == this policy
    let terms = terms_of(&dep.4);
    assert!(payout.to_string() == terms.payout, "payout is fixed by the credit line");

    let chain = atp_verify::verify_plc_chain(&did, &slices(&ops)).expect("bad chain");
    assert!(chain.extends(self.chain_pin(&did)), "stale operation chain");
    // ES256K signature by the account's repo key; then check who issued it, for whom, for what
    let claims = atp_verify::jwt::verify_service_auth(&token, &chain.signing_key).expect("bad token");
    assert!(claims.iss == did && claims.aud == terms.provider);
    if !terms.lxm.is_empty() { assert!(claims.lxm.as_deref() == Some(terms.lxm.as_str())); }
    assert!(self.spent.entry(did.clone()).or_default().insert(hex(&sha256(token.as_bytes()))),
        "this token was already redeemed");

    // release the line, pay one call, re-escrow the rest under the same terms (policy_deposit)
    // or, if it can't cover another call, keep it as change the payer takes back
    let mut funds: Bucket = self.release(&did, index);
    ComponentManager::get(payout).invoke("deposit", args![funds.take(Amount::from(terms.price))]);
    self.reescrow_or_keep_change(did, dep, funds);
}

Because the payout is fixed in the deposit, a leaked token can only ever pay the provider the user already chose, and only once. A method-scoped line (lxm) pays only tokens minted for that one XRPC method. The verifier returns exp but cannot enforce it — a WASM contract has no wall clock — so single use, not expiry, is what bounds a token on-chain.

List-gated drops: the org vouches

It's tempting to airdrop to every account whose chain lists a *.yourorg.com handle, but that check is worthless: alsoKnownAs is self-asserted, and anyone can write ceo.yourorg.com into their own chain. Membership has to be signed by the org. A Bluesky list is exactly that: every app.bsky.graph.listitem in the org's repo names a member DID and its list. ListDrop pays one slot per member who proves such an item, plus a claim-code post of their own that binds the payout to their wallet.

list_drop/src/lib.rs (the checks in claim)

// slot metadata = snapshot (µs, 8 BE) ++ "at://<org did>/app.bsky.graph.list/<rkey>"
let terms = terms_of(&meta);

// 1. the org vouches: a listitem in the ORG's repo, for this member, on this list
let org = atp_verify::verify_plc_chain(&terms.org, &slices(&org_ops)).expect("bad org chain");
assert!(org.extends(chain_pin(&terms.org)));
atp_verify::verify_record(&terms.org, &org.signing_key, l_commit, &l_nodes, l_record,
    "app.bsky.graph.listitem", &l_rkey).expect("bad listitem proof");
assert!(atp_verify::field_eq(l_record, &["subject"], &did));
assert!(atp_verify::field_eq(l_record, &["list"], &terms.list));
// from a commit made at or after the snapshot: items added and removed before it count for nothing
assert!(atp_verify::commit_rev_micros(l_commit)? >= terms.snapshot);

// 2. the member binds the payout (code commits to policy, campaign, DID and wallet key)
let chain = atp_verify::verify_plc_chain(&did, &slices(&ops)).expect("bad chain");
assert!(chain.extends(chain_pin(&did)));
atp_verify::verify_record(&did, &chain.signing_key, c_commit, &c_nodes, c_record, "app.bsky.feed.post", &c_rkey)?;
assert!(atp_verify::record_text(c_record)?.contains(&claim_code(me, &campaign, &did, &claimant)));

A record proof shows the item existed at that commit, not that it still does, so someone removed from the list after the snapshot can still claim with a commit from between. Set the snapshot to the moment the list is final. Funder-namespaced campaigns and one claim per DID work as in the bounty.

Social recovery by guardian posts

SocialRecovery lets a vault owner name up to seven guardian DIDs and a threshold in the deposit's metadata (threshold ++ delay ++ guardian DIDs). If the owner loses their key, guardians each publish a recovery code naming the new owner's account. Once the threshold agrees on the same new owner, a delay starts; the owner can veto it with their key until it ends, and after that anyone can execute and the funds go only to the account the guardians chose.

expected_post_text(vault_id, index, new_owner)

The code a guardian posts. It commits to this policy, this vault and the new owner, so an approval can't be lifted onto another vault or redirected to another account.

approve(vault_id, index, guardian, new_owner, ops, commit, nodes, record, rkey)

Anyone relays a guardian's post. Proven against the guardian's current chain (floor-checked). Each approval must use a newer post than that guardian's last, so after a veto an old post can't be replayed; approvals for different new owners never add up.

cancel(vault_id, index)

The owner, still holding their key, vetoes a pending recovery — the defence against colluding guardians.

execute(vault_id, index, new_owner)

After the delay, pays the vault into the chosen account with release_to.

The claim lifecycle

Policies that need a dispute period (like Skydrop's) split the claim in two and add a challenge. A PLC log cannot be proven complete, so a window lets a newer, rotated-away key cancel a stale claim before payout.

start_claim(did, claimant, proof…)

Verify the coded post and record a pending claim at the current epoch, stamped with the chain's length and tip.

challenge(did, ops)

Anyone, during the window: present a longer or different valid chain to cancel the pending claim. Guards against a stolen, already-rotated key.

finalize_claim(did) → Bucket

Release every deposit whose window has elapsed since the claim started, merged into one bucket. Deposits still inside their window stay escrowed.

// finalize: release each payable deposit, newest index first so removals
// don't shift the ones still waiting, then merge with Bucket::join.
let mut payout: Option<Bucket> = None;
for i in payable_indices {        // now >= start + window_of(metadata)
    let proof = self.badge_vault.create_proof();
    let b: Bucket = ComponentManager::get(self.escrow).call("release", args![proof, did.clone(), i]);
    proof.drop();
    payout = Some(match payout { Some(acc) => acc.join(b), None => b });
}
Trust boundary to honor. Everything the layer trusts is bound by a signature or a hash. The CBOR reader does not enforce canonical form on purpose — it is safe only because non-canonical bytes let an account mangle its own data, never forge another's. Any new path that reads a field without a covering signature or hash breaks that guarantee.
